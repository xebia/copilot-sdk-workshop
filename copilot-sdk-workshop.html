var getBuildStatus = CopilotTool.DefineTool( ([Description("Project name")] string project) => { return project.ToLowerInvariant() switch { "frontend" => new { project, status = "passing" }, "api" => new { project, status = "failing" }, "database" => new { project, status = "passing" }, _ => new { project, status = "unknown" } }; }, factoryOptions: new AIFunctionFactoryOptions { Name = "get_build_status", Description = "Gets the current build status for a project." });

Tool design

Small. Clear.
Deterministic.

BAD
manage_project()
BETTER
get_build_status()
get_deployment_status()
restart_service()

Names and descriptions are how the model chooses. Return structured, predictable results. The model reasons over the result. The tool does the deterministic part.

Same principle as deterministic guardrails: let AI handle ambiguity, let normal code handle what normal code is better at.

Context isolation: a sub-agent works a focused task and returns a summary instead of stuffing everything into the parent context.
